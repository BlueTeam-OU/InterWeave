# Release rows: v0.4.0's archive passes Stage 19's host Validate rows, 2026-11-24

Stage 19 (plan section 22) gives rust-ui-dev six Validate rows "as host
tests against a packaged build": fresh install, upgrade, rollback,
profile/config migration, `PeerId` preservation and the recovery drill.
Their tests are `tests/desktop-e2e/tests/human_app/release.rs`. CI runs
them with `INTERWEAVE_PACKAGE_BIN` unset, so against the workspace's own
build. This record runs them once against the programs in the published
`v0.4.0` Linux archive. The archive and the tag are checked first,
against the keys pinned on `main` (ADR-0066). The run was asked by
architect-cto for the project's close (REQUEST 01a20011-7559, job j131).

The check is the script below, run once from the top. Its trace
(`set -x`, `PS4='$ '`) follows: every command as the shell ran it, in
order, then its output. The trace ends with the script's exit status,
which `echo "exit=$?"` printed after it. The trace is edited in four
ways and no other:

- the account's home directory is written `~`;
- the session's scratch directory is written `<scratch>`;
- the address in the tag key's user id is written `<the owner's address>`;
- cargo's 702 `Compiling` lines are left out. Every other line of the
  build is kept, its `Finished` lines included.

How it was set up:

- The repository it reads is the working copy of this change, and
  `origin/main` there is fetched first. The key files are `main`'s
  copies, written by `git show origin/main:...`.
- The cases run from a second, clean worktree of the same repository,
  checked out detached at the tag, with a cargo target directory of its
  own.
- `INTERWEAVE_PACKAGE_BIN` names the extracted archive's `bin/` by its
  absolute path. It is set for the two `cargo test` runs and for nothing
  else.
- The previous-build axis is built by the tag's own
  `tools/ci/build_previous_builds.sh`, from the tag's
  `tools/ci/previous-builds.txt`, as CI builds it. The rollback row is
  `#[ignore]`d without that axis, so it runs second, with
  `INTERWEAVE_PREVIOUS_BUILDS` set as well.
- Both runs are under the tag's `tools/ci/with_display.sh`, the private
  X display and AT-SPI bus CI gives the desktop cases.

## Which row is which case

| Validate row | case in `release.rs` at `v0.4.0` | result |
|---|---|---|
| fresh install | `a_fresh_install_keeps_the_peer_id_init_printed` | ok |
| upgrade | `an_upgrade_reads_everything_the_previous_build_kept` | ok |
| rollback | `a_rollback_to_each_previous_build_keeps_the_peer_id_and_is_recorded` (real older daemon and `transportctl`), `a_store_from_a_newer_build_stops_the_client_and_is_left_as_it_was`, `an_encrypted_store_from_a_newer_build_stops_the_client_and_is_left_as_it_was`, `an_overlay_or_profile_from_a_newer_build_stops_the_daemon_and_is_left_as_it_was`, `a_profile_a_newer_build_marked_stops_every_program_and_is_left_as_it_was` | ok |
| profile/config migration | `an_upgrade_reads_everything_the_previous_build_kept`, over the committed tree; see the limit below | ok, with the limit |
| `PeerId` preservation | asserted by every case above | ok |
| recovery drill | `the_recovery_drill_restores_the_same_peer_id_and_never_mints_one` | ok |

`write_the_previous_build_tree` is `#[ignore]`d in both runs. It writes
`test-data/upgrade/<commit>/` and is not a Validate row.

## The script

```bash
#!/usr/bin/env bash
# Stage 19's six Validate rows (release.rs) against a release archive, run once from the top; its trace is the record.
# Usage: release_rows.sh <tag> <repository clone> <worktree for the cases> <cargo target dir>
set -euo pipefail
TAG=$1 REPO=$2 TREE=$3 TARGET=$4
PS4='$ '
set -x
whoami
hostname -s
grep -E '^(NAME|VERSION)=' /etc/os-release
ldd --version | head -1
minisign -v
R=$(mktemp -d)
git -C "$REPO" fetch --quiet origin
git -C "$REPO" fetch --quiet origin tag "$TAG"
git -C "$REPO" show origin/main:tools/ci/release_keys.py > "$R/release_keys.py"
git -C "$REPO" show origin/main:packaging/release-keys.toml > "$R/release-keys.toml"
RUN=$(gh run list -R BlueTeam-OU/InterWeave --workflow release.yml --branch "$TAG" --limit 1 --json databaseId -q '.[0].databaseId')
gh run view "$RUN" -R BlueTeam-OU/InterWeave --json conclusion,jobs -q '"run: \(.conclusion)", (.jobs[]|"\(.conclusion)  \(.name)")'
mkdir -m 700 "$R/gnupg"
python3 "$R/release_keys.py" "$R/release-keys.toml" tag.public_key | GNUPGHOME="$R/gnupg" gpg --batch --import
GNUPGHOME="$R/gnupg" git -C "$REPO" -c gpg.program=gpg verify-tag "$TAG"
git -C "$REPO" rev-parse "$TAG^{commit}"
cd "$R"
gh release download "$TAG" -R BlueTeam-OU/InterWeave -p "interweave-${TAG#v}-x86_64-unknown-linux-gnu.tar.gz*"
A="interweave-${TAG#v}-x86_64-unknown-linux-gnu.tar.gz"
PK=$(python3 release_keys.py release-keys.toml archive.minisign_public_key)
minisign -V -P "$PK" -m "$A"
minisign -V -P "$PK" -m "$A.sha256"
sha256sum -c "$A.sha256"
cp "$A.sha256" tampered.sha256
sed -i '1s/^./0/' tampered.sha256
if minisign -V -P "$PK" -m tampered.sha256 -x "$A.sha256.minisig"; then echo "TAMPERED COPY ACCEPTED"; exit 1; fi
tar -xzf "$A"
BIN="$R/${A%.tar.gz}/bin"
ls "$BIN"
"$BIN/transport-daemon" --version
"$BIN/transportctl" --version
"$BIN/interweave-human" --version
for b in "$BIN"/*; do printf '%s ' "${b##*/}"; objdump -T "$b" | grep -o 'GLIBC_[0-9.]*' | sort -uV | tail -1; done
objdump -T "$BIN/human-desktop" | grep 'GLIBC_2.35'
objdump -p "$BIN/human-desktop" | grep NEEDED
cd "$TREE"
git status --porcelain
git checkout --quiet --detach "$TAG"
git rev-parse HEAD
git grep -c workspace_binary -- tests/desktop-e2e/tests/human_app || true
export CARGO_TARGET_DIR="$TARGET"
bash tools/ci/build_previous_builds.sh "$R/previous-builds"
ls "$R/previous-builds"/*
INTERWEAVE_PACKAGE_BIN="$BIN" bash tools/ci/with_display.sh cargo test --locked -p interweave-desktop-e2e-tests --test human_app -- release:: --test-threads 1
INTERWEAVE_PACKAGE_BIN="$BIN" INTERWEAVE_PREVIOUS_BUILDS="$R/previous-builds" bash tools/ci/with_display.sh cargo test --locked -p interweave-desktop-e2e-tests --test human_app -- --ignored --exact release::a_rollback_to_each_previous_build_keeps_the_peer_id_and_is_recorded
```

It was run as
`release_rows.sh v0.4.0 <this working copy> <a clean worktree> <a target directory>`.

## The glibc floor, as the trace measures it

The archive's `human-desktop` needs `GLIBC_2.35`, and its only symbol
at that version is `hypotf`. `interweave-human`, `transport-daemon` and
`transportctl` need `GLIBC_2.34`. `human-desktop`'s `NEEDED` entries
are `libgcc_s`, `libm`, `libc` and `ld-linux` and nothing else.

That agrees with the floor of glibc 2.35 that ADR-0065 decision 2 sets
and the release run gates (its job "release archive runs at glibc 2.35"
passed, above). It also means a glibc 2.34 system runs the daemon,
`transportctl` and the command-line client but not the GUI. This host
runs glibc 2.42, so the run itself proves nothing about the floor.

## What this does not show

- **Profile/config migration across a format change.** Upgrade is
  proved over the committed previous-build tree
  (`test-data/upgrade/d3a193e9`), whose formats are this build's own. No
  tree with an older format is on the axis. So an upgrade across a
  format change is proved for each artefact on its own (the store's
  migrations in `crates/human/store`, the profile-format marker), and
  not end to end. That is this row's limit (`release.rs`'s module
  comment at the tag says the same).
- **An older client.** The axis holds one previous build, which is no
  published release. It holds an older daemon and `transportctl` and no
  older `human-desktop`, so the rollback row runs no older GUI over this
  build's tree.
- **The display libraries the GUI loads at run time.** They are not
  `NEEDED` entries, so the objdump lines above do not list them, and
  nothing here inventories them.
- **An install.** `install.sh`, the user units and the desktop launcher
  were not run. The programs started from the extracted `bin/`, each
  bare with `--profile` and the XDG variables, as `release.rs` starts
  them. The units' own row is `user_units.rs`'s, which is
  p2p-network-dev's.
- **A host other than this one**, and any desktop but the private Xvfb
  display.
- Who signed the tag, and where. The trace shows only that the pinned
  key made the signature, not whose hand or account used it.
- The APK. Nothing here installs or runs it.

# InterWeave Claude Code plugin

The plugin that starts the Channel bridge, `apps/claude-channel`, inside Claude Code (`architecture/plugin/PACKAGING.md`, plan §19 step 3).

- `.claude-plugin/plugin.json` declares one channel, whose `server` is the `.mcp.json` key that starts the bridge. With `author` present it passes `claude plugin validate --strict` (SPIKE-001 fact 8).
- `.mcp.json` starts `bin/claude-channel` with the plugin's routing configuration: the transport profile's name and the local endpoint the bridge claims, as `${user_config.profile}` and `${user_config.endpoint}`. `plugin.json` declares both as `userConfig`, defaulting to the conventional `default` and `claude`, and `claude plugin install interweave@interweave --config profile=<p> --config endpoint=<e>` sets them, with no file edited (SPIKE-001 S20). A third setting, `log_level` (`error`, `warn`, `info` or `debug`, default `info`), is passed as `--log-level`: how much the bridge writes to stderr and to its own log file. It also passes `--delivery push`, which stays: Claude Code receives by the channel notification, and the bridge requires the mode. The bridge never chooses another endpoint on a conflict (`plugin/LIFECYCLE.md` §Endpoint conflict).
- `.claude-plugin/plugin.json`'s `version` is the placeholder `0.0.0`. `build.sh` writes the release version into the copy it assembles: `[workspace.package] version` from the root `Cargo.toml`, which every first-party crate inherits (ADR-0065). It refuses a `--version` that is not that value, which is how the release run passes its own. A marketplace loaded from this directory directly is at `0.0.0`.
- `bin/claude-channel` is the built binary (`cargo build --release -p interweave-claude-channel`), copied in at packaging time and not committed.

A release ships this marketplace already assembled, as `claude-plugin/` in the Linux release archive (`tools/ci/release_linux_archive.sh`), with the release `claude-channel` inside it. From a checkout, `packaging/claude-plugin/` is also a Claude Code marketplace: `.claude-plugin/marketplace.json` lists this plugin as `./interweave`, and `packaging/claude-plugin/build.sh <out-dir>` assembles it, with the release binary in `interweave/bin/`, into a new directory outside the tree. It copies exactly the files git tracks here and fails the build if the source holds any file git does not track, ignored ones included, so a stale `bin/claude-channel` left in the tree never ships (`apps/claude-channel/tests/packaging_build.rs`). `claude plugin marketplace add <out-dir>` then `claude plugin install interweave@interweave` installs it; the marketplace manifest carries `metadata.description` because `claude plugin validate --strict` on Claude Code 2.1.286 asked for it. That validation was run by hand on 2026-10-20 and is not a committed run; SPIKE-001's `v1-validate` covers only the spike's own plugin, on 2.1.285.

Loaded with `--plugin-dir`, the plugin is inline: its server is named `plugin:interweave:interweave` and the channel flag value is `plugin:interweave@inline`. Channel events reach the model only in an interactive session started with `--dangerously-load-development-channels plugin:interweave@inline` and accepted on its warning screen (SPIKE-001 facts 4-7). Installed from the marketplace, the server has the same name and the flag value is `plugin:interweave@interweave`. The development flag registers it the same way (SPIKE-001 S19, facts 20-22, Claude Code 2.1.286). Without that flag, `--channels plugin:interweave@interweave` registers it when the host's managed settings list `{"plugin": "interweave", "marketplace": "interweave"}` in `allowedChannelPlugins`, with `channelsEnabled: true`, and is refused without that entry, since the plugin is not on Anthropic's allowlist (SPIKE-001 S22, facts 29-33, Claude Code 2.1.286). `INSTALL.md` step 7 is that setting. With that setting and `--channels plugin:interweave@interweave`, or the stream-json control request `channel_enable` in its place, a non-interactive `claude -p` session with stream-json input held open receives the channel too; the setting alone gives it none, and on the runs made the development flag gave such a session nothing (SPIKE-001 S24, facts 39-41, Claude Code 2.1.286).

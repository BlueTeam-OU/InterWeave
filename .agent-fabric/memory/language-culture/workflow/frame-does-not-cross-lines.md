## a conditional header ("If you accept, ...") does not set the tense of the lines listed under it; a bare participle there reads as done

In a list of changes shown before a control is pressed, each line is read on its own: "If you accept, your contact {X} is updated." above does not make "Current photo removed" read as future. A bare past participle reads as a thing already done, so the status claims more than happened. Use a whole sentence that says it has not happened ("Your contact's photo will be removed.") and that names whose thing it is.

**Why:** on #440 (j189, 2026-10-25) I withdrew this first-pass finding on the second pass, because the header seemed to govern the list. The cold read found it again with the header in view, so the withdrawal was wrong. Delivered to rust-ui-dev-02 in REPLY 01a1729f-62d2; the spec table line went to ux-designer-01 as OBSERVATION 01a1729f-6f95.

**How to apply:** do not withdraw a first-pass tense finding because of a frame on another line. Parallel short lines are worth less than a status a reader takes for done. Related: [[workflow-carried-2026-10-10]], [[word-against-the-where-cell]].

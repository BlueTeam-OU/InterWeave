# Gate (b) device runs, 2026-10-20

Plan §20 gate (b): "instrumented tests on a real device (API level
recorded) for each line of 'Platform tests'". These lines were not
instrumented cases on the day of the window. architect-cto-01's rule
(INFO 01a15915) applies: run them by hand, read them through logcat
and dumpsys, and record the steps and what was seen here. The
instrumented cases are carried by name to the next branch.

Devices:
- **Samsung A40**: SM-A405FN, Android 11, API 30. Destructive steps
  are allowed on it, at the owner's word.
- **Pixel 9a**: Android 17, API 37. Non-destructive steps only, at the
  owner's word: the app's data stays.

Every adb step went through `.agent-fabric/bin/phone-run`, and its
helper is `line.sh` (in the run's scratch, quoted below). The
person-facing steps were done by the owner's hands. The app's window
is FLAG_SECURE whenever an identity is not ready, so screencap gives
nothing there; the owner read those screens.

### A defect found: Show recovery phrase refused as Busy after a Back

The sequence was: Show recovery phrase, words shown, the phrase left,
then Back at 22:57:06. That closed one MainActivity instance and
returned to another in the same task. Every later Show recovery
phrase failed with "The app could not go offline" (`IdBusy`); logcat
shows "an identity write was refused: Busy" five times, and no
"stopped:" line.

Cause, from the code: the service binding is the application's, but
each instance's `onStop` lets it go. The closing instance unbound the
binding the surviving instance relied on. With no binding, Ask.OFFLINE
calls `Native.offline(true)` on the assumption that no service runs
then. Under stay-reachable the foreground service still runs and
holds the profile lock. A force-stop and relaunch cleared it. Fixed in
225f7558 (the binding is let go by the last started instance only; with
no binding, going offline binds and stops the service), with a pending
offline answered on the last stop in 1a8ff67e.

Repeated on build 1a8ff67e (APK fd2d2708…, install -r), the owner's
hands: Show recovery phrase, the phrase finished, Back, then Show
recovery phrase again, several times. The words show every time; no
"could not go offline".

### A defect found: the surviving copy dead after a second one closed

With two MainActivity instances in the task (a launch over a running
one), closing the top one left the one below drawn and dead to every
touch and Back. Cause, from the code and logcat: the views run one
event loop (`android_main`), bound to the Activity that started it;
when that instance closed, "android_main: the Activity's views end"
was logged and nothing drew input again. Fixed in a4b40c99:
MainActivity is `singleTask`, so a launch while one exists is
delivered to it.

Repeated on build a4b40c99 (APK 338cbf0e…, install -r): a second
`am start` of MainActivity answered "intent has been delivered to
currently running top-most instance"; the task holds `sz=1` and the
views started once. The owner's hands: the app reopened on Chats and
responded; Show recovery phrase showed the words after the PIN; Back
from the words landed on Trust, where no window carries SECURE.

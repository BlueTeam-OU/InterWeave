# Samsung A40 device run, 2026-11-05: a release first run onboards

The check j96 owed #569: a fresh install of the RELEASE build creates an
identity. The release APKs of v0.1.0 and v0.2.0 do not: their library
writes no profile document, so onboarding's seal is refused at C4's
Continue, "the profile document cannot be read" (p2p-network-dev-01's
run on this phone the same day, `packaging/android/evidence/` on #570).

Device: **Samsung A40**, SM-A405FN, Android 11, **API 30**, the phone of
`2026-11-04-samsung-a40.md`. Every adb step ran on this login's own adb
server (port 15065) under the `samsung-a40` lease, over wireless
debugging; no adb process of this login remained after any run
(`pgrep -u "$(id -u)" -a adb` empty). The phone's clock reads UTC+1;
every time below is UTC.

Before: release v0.2.0 (versionCode 2, signer `520af074`) with no
identity, as p2p-network-dev-01 left it after their j141.

Build: the RELEASE variant of 9aba4c441 (#569's head with main folded),
`./gradlew :app:assembleRelease` here, which runs `verifyReleaseNative`
(the library carries the first-run writer's marker; v0.2.0's has none).
The release key is not this login's, so the unsigned APK was aligned and
signed with a test-only key made for this run (certificate SHA-256
beginning 50a50bf8, signer `8f75414f` on the phone; APK sha256
beginning 1b0d6c6d). The manifest is not debuggable. Its versionName
reads 0.2.0: the workspace version is unchanged (a patch, cut by the
owner).

## Steps

15:44:55, keyguard showing: `adb uninstall org.interweave.human`
(another signer will not install over v0.2.0), then `adb install` of the
test-signed APK, `logcat -c`, and a launcher start.

```text

```

The owner then unlocked the phone and went through Create by hand (the
onboarding window is `FLAG_SECURE`) to "Identity created" (C4) and its
Continue. The log, read at 15:48:31:

```text
11-05 16:48:22.892  3425 13123 I interweave: the runtime started with the networks: 2 addresses (0 on no local network), 2 resolvers, strict Private DNS off
11-05 16:48:22.892  3425 13123 I interweave: start answered 0
```

No "an identity write was refused" line. The Service started with an
identity, which a release start does only once the record exists
(`FirstRun::Refuse` answers `NO_IDENTITY` otherwise): the seal
succeeded at C4's Continue.

## What it shows

| case | result |
|---|---|
| a fresh install of the release build writes its profile and onboards | yes, at API 30 |

## What it does not show

- The release KEY: the APK was test-signed. What the release key's
  signing adds, the release run (`tools/ci/release_android_apk.sh`)
  checks; it changes nothing the native library does.
- Restore from a recovery phrase on a release build.
- An update in place from v0.2.0 onto a fixed release, and that a phone
  updated so writes its profile then: the signers differ here, so the
  old release was uninstalled first.
- The Pixel 9a at API 37.
- What the person saw after Continue: the window is `FLAG_SECURE`, and
  the owner's word was "done".

After the run the phone carries this test-signed release build with the
owner's new identity.

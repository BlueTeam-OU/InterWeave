## The pane on the fixed debug build (job j90, 18:26-18:35)

What job j90 owed after `2026-11-04-samsung-a40.md`'s "The pane on an
optimised build": the conversation open on the debug build as it now
ships, its native library at the release opt-level (90dfbdb7c), where
the unoptimised one stalled the UI thread 7.7 to 12.3 s with two ANRs.

Build: the debug and androidTest APKs of 05e7ab70f (90dfbdb7c with
main folded), `./gradlew :app:assembleDebug
:app:assembleDebugAndroidTest`; cargo reported the library's profile as
`dev profile [optimized + debuginfo]`. App APK sha256 beginning
66af1d18, test APK 4db8c691, signer `26d1eb18` on the phone. On the
owner's word in the session ("Yes, wipe it"), the release build above
was uninstalled at 18:26 with the owner's identity, since a debug
signer will not install over it, and these installed fresh. The
identity the cases use is the one the e2e runner creates on a first run
(`FirstRun::Create`).

The conversations: `tests/android-e2e/tests/human_chat.rs`'s two device
cases, run from the host with `--ignored --test-threads 1`, both
**passed** at 18:30 (24.1 s). Each left the phone one conversation from
D with three unread messages, one of them the compressible list of some
900 lines. The owner unlocked the phone; the app was started cold and
measured as on 2026-11-04, on the phone's own clock: one `adb shell`
that dates, sends a key by `input keyevent`, dates again (on API 30
`input` returns once the app has handled the key), and takes a frame.
Portrait.

to 0.6 s over the `input` tool's own second, against 0.2 s on
2026-11-04's `--release` library: the debug assertions and overflow
checks that stay cost something, and the 7.7 to 12.3 s stall is gone.

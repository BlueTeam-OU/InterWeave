# store

SQLite implementation of pending_outbound, unread_inbound, kept_inbound, contacts/preferences; deliberately no general durable history API.

**Current status:** Stage 3, active workspace member. The three ADR-0044 states as its only content: pending outbound, unread inbound, and inbound the receiver explicitly kept. Beside them, content-free metadata that cannot reconstruct a deleted body: `settings`, and since schema v5 `contacts`, `contact_routes` and `conversation_index`, each checked column by column. Since v6 each pending row also carries the transport `MessageId` its first send minted and every retry reuses, so a retry after restart is deduplicated by the receiver. Since v7, `read_pairs` records each message read and not kept by its origin and application id alone: a later copy is refused as `AlreadyRead`, a duplicate, so a message read before a restart is not unread again. At most `READ_PAIR_CAP` (4096) pairs are held, the oldest evicted in the transaction that records the newest (STATE.md; architect-cto's Q5 ruling). `unkeep` returns the session copy for a re-keep (Q6) and records a pair too. Since v10 (the start window, STATE.md), `contacts.name_key` and an inbound row's `kind` (`text`, `card`, `other`) are derived, content-free columns, each recomputed at open when its version differs, and seven indexes serve the start's reads: a conversation a page at a time (`conversation_page`), the badge's counts (`unread_counts`), the rows this build cannot show (`hidden_inbound`), the contacts without their photos (`contact_directory_page`), and a card's standing by name. Since v11 the kept rows' kind index carries the conversation's columns too, so the conversations a client shows are read from the two kind indexes alone (STATE.md). `verify_shape` refuses any other table, view, or trigger on every open, so the absence of a general history API is enforced rather than merely intended. A client opens it with `HumanStore::open_profile(&ProfilePaths, ..)`: `STORE_FILE` in the profile's human directory, judged by ADR-0028's walk up to the trust boundary the paths carry (`/` on the desktop, the app's data directory in an embedded layout); `open(path, ..)` judges up to `/`.
